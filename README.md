### 🚧 Сервис управления доступом и биллингом шлагбаума
Автономный веб-сервис для жильцов и модератора шлагбаума поселка. Система закрывает сквозной проезд для посторонних, автоматизирует проверку платежей (чеков), ведет учет баланса с учетом грейс-периода и генерирует выгрузку номеров телефонов в формате CSV для шлагбаума.

## 🧠 Архитектура и логика «под капотом»

Система разделена на два независимых контура:
* **Кабинет Жителя (`/dashboard`):** житель видит текущее состояние проезда (дни и дату), может загрузить PDF/фото чека об оплате, отслеживать статус проверки своих чеков модератором (с причинами отказа при отклонении), менять контакты/автомобиль и личный пароль.
* **Панель Модератора (`/admin` и `/admin/users`):** модератор одобряет/отклоняет чеки, управляет реестром жителей, запускает перерасчёт долгов, видит готовую SMS-очередь изменившихся номеров и скачивает полный CSV-файл для контроллера.

Все расчёты срока действия привязаны к полю `paidUntil` (дата, до которой оплачен доступ).

---

## 💰 Бизнес-логика: тариф, статусы и вступительный взнос

### 1. Тариф
* **Базовая стоимость:** **2,5 ₽ в день** (~75 ₽ в месяц).
* **Вступительный взнос:** **700 ₽** (разовый платёж за первые 2 номера при подключении).

---

### 2. Логика вступительного взноса при создании жителя
Когда администратор создаёт жителя вручную через форму `/admin/users/create`:

* **Чекбокс «Вступительный взнос оплачен» ВКЛЮЧЕН (`entranceFeePaid: true`):**
  * Считается, что житель сдал разовый взнос.
  * Жителю начисляется ровно **1 тестовый/стартовый день** пользования от текущей даты (`paidUntil = сегодня + 1 день`).
  * Статус выставляется в **`active`** (проезд открыт).
* **Чекбокс «Вступительный взнос оплачен» ВЫКЛЮЧЕН (`entranceFeePaid: false`):**
  * Жителю начисляется долг в размере взноса (700 ₽).
  * В днях долга: $700 / 2,5 = 280$ дней.
  * Дата оплаты сдвигается глубоко в прошлое: `paidUntil = сегодня - 280 дней`.
  * Статус сразу устанавливается в **`disabled`** (проезд заблокирован).

---

### 3. Редактирование жителя администратором (Установка галочки взноса позже)
Если должнику (со статусом `disabled` и отрицательным балансом) в карточке редактирования `/admin/users` администратор **включает галочку «Вступительный взнос оплачен»**:
1. Система распознаёт закрытие вступительного взноса.
2. Дата `paidUntil` автоматически сбрасывает старый долг и становится равной **текущая дата + 1 день**.
3. Статус принудительно переключается в **`active`**.
4. Номер жителя автоматически отправляется в очередь шлагбаума на добавление (`add`).

---

### 4. Статусы жителя и расчёт просрочки (Биллинг)

Перерасчёт запускается по кнопке **«⚡ Пересчитать долги»** или по расписанию:

| Статус | Описание | Проезд | Условие перехода |
| :--- | :--- | :---: | :--- |
| **`active`** | Активен | **Да** | `paidUntil` больше текущего дня. |
| **`grace`** | Льготный период | **Да** | Просрочка от 1 до 7 дней включительно. Житель видит предупреждение о необходимости внести оплату. |
| **`disabled`**| Заблокирован | **Нет** | Просрочка более 7 дней. Номер удаляется из базы шлагбаума. |
| **`frozen`** | Заморожен | **Нет** | Ручная заморозка (отпуск/пауза). Срок действия `paidUntil` сдвигается на количество дней заморозки при возврате в статус `active`. Биллинг не блокирует замороженного жителя. |

## 📡 Синхронизация со шлагбаумом (CSV и SMS-очередь)

Для передачи данных в контроллер шлагбаума предусмотрено два механизма:

### А. Полная выгрузка CSV (`/api/admin/export-csv`)
Используется при первичной прошивке или регулярной синхронизации базы контроллера.
* **Администратор ВСЕГДА стоит на 1-м месте** сразу после заголовков (ID 1).
* В выгрузку попадают только разрешённые пользователи со статусами **`active`** и **`grace`**. Заблокированные (`disabled`) и замороженные (`frozen`) номера исключаются.
* **Формат файла:** точка с запятой в качестве разделителя, кодировка UTF-8 с BOM-меткой (`\ufeff`) для поддержки GSM-модулями и Excel.

Пример структуры `barrier_phones.csv`:
    ```csv
        id;telephon;out
        1;+79012345678;0
        2;+79181112233;0
        3;+79184445566;0
    ```

### Б. Очередь изменений для SMS-обновлений (Коллекция BarrierQueue)
Используется, когда за неделю сменилось 1–5 номеров и проще отправить одну сервисную SMS-команду контроллеру шлагбаума, чем заливать весь CSV-файл.

* **Как это работает:**

При любом событии (биллинг заблокировал должника, модератор принял чек, закрыт вступительный взнос или включена заморозка) система пишет событие в коллекцию BarrierQueue.

В панели модератора появляется карточка «Очередь изменений для шлагбаума»:
🟢 Добавить: строка номеров через запятую для добавления в память шлагбаума + кнопка «Скопировать».
🔴 Удалить: строка номеров через запятую для удаления + кнопка «Скопировать».
После отправки SMS администратор нажимает «✓ Отметить как отправленные», и очередь сбрасывается.

### 🔐 Безопасность и Переменные окружения (.env)
Никогда не выгружайте реальный файл .env или .env.local в публичный репозиторий! Файл .gitignore уже настроен на их игнорирование.
Для запуска проекта создайте локальный файл .env.local на основе шаблона .env.example:

Шаблон .env.example
`
    # Подключение к MongoDB
    # Формат: mongodb://<пользователь>:<пароль>@<host>:<port>/<dbname>?authSource=admin
    MONGODB_URI=mongodb://admin:your_password@127.0.0.1:27017/имя_db?authSource=admin

    # Настройки NextAuth
    NEXTAUTH_SECRET=your_random_secret_key_change_me
    NEXTAUTH_URL=http://localhost:3000

    # Timeweb Cloud S3 к примеру
    S3_ENDPOINT=https://s3.timeweb.cloud
    S3_REGION=ru-1
    S3_BUCKET_NAME=your_bucket_name
    S3_ACCESS_KEY=your_access_key
    S3_SECRET_KEY=your_secret_key 
`

### 🔑 Авторизация и Разграничение доступа
Авторизация построена на NextAuth.js с использованием стратеги JWT-токенов.
Логин: Номер телефона пользователя (например, +79991112233).
Пароль: Хешируется с помощью bcrypt (10 раундов salt).

Маршрутизация и Права Доступа:
1. Неавторизованный пользователь:
    - Доступен только маршрут /login.
    - При попытке зайти на /, /dashboard или /admin автоматически перенаправляет на /login.
2. Житель (role: 'user'):
    - При входе перенаправляется на /dashboard.
    - Имеет доступ к загрузке чеков и просмотру своего баланса.
    - При попытке зайти в /admin перенаправляется в /dashboard.
3. Модератор (role: 'admin'):
    - При входе перенаправляется на /admin.
    - Имеет полный доступ к очереди чеков, сбросу паролей всех жильцов, запуску биллинга и выгрузке CSV.


### 🌱 Для чего нужен scripts/seed.js?
Поскольку пароли в базе хранятся только в захешированном виде, вручную создать пользователя через GUI (MongoDB Compass) нельзя — он не сможет войти.
Скрипт scripts/seed.js служит для первичного наполнения базы данных. Он подключается к MongoDB и автоматически создает два готовых аккаунта:
Модератор: Телефон +79012345678, Пароль password123, role: 'admin'.
Тестовый житель: Телефон +79991112233, Пароль password123, role: 'user'.

Запуск скрипта:
    `
        npm run seed
    `


### 📡 Описание всех API Маршрутов
🔑 Авторизация
   - POST /api/auth/[...nextauth] — обработка входа через CredentialsProvider, проверка хеша пароля в MongoDB, выдача JWT-сессии.

👤 Пользователь (Житель)
   - GET /api/user/profile — получение баланса, дней и контактов авторизованного жителя.
   - POST /api/user/update-profile — сохранение обновлённых ФИО, авто и смена пароля.
   - GET /api/user/payments — список последних 10 чеков жителя с их статусами и причинами отказа.
   - POST /api/payments/upload — загрузка чека в Timeweb Cloud S3 и создание записи платежа.

🛡️ Панель Модератора (role: 'admin')
   - GET /api/admin/payments — очередь чеков со статусом pending.
   - POST /api/admin/payments — одобрение (с продлением paidUntil) или отклонение чека с комментарием.
   - POST /api/admin/cron-billing — перерасчёт статусов просрочки по датам и наполнение очереди BarrierQueue.
   - GET /api/admin/export-csv — скачивание файла номеров barrier_phones.csv (администратор на 1-м месте).
   - GET /api/admin/barrier-queue — получение списка номеров для SMS (сгруппировано по add / remove).
   - POST /api/admin/barrier-queue — сброс очереди после отправки SMS-команд.
   - GET /api/admin/users — список всех жителей для таблицы.
   - POST /api/admin/users — ручное добавление жителя (с расчётом взноса).
   - PUT /api/admin/users/[id] — редактирование данных жителя, закрытие взноса или изменение дат/статусов.


### ⚡ Инструкция по локальному запуску
1. Клонировать репозиторий:
    `
        git clone [https://github.com/your-repo/barrier-service.git](https://github.com/your-repo/barrier-service.git)
        cd barrier-service
    `
2. Установить зависимости:
    `
        npm install
    `
3. Настроить окружение:
Создайте файл .env.local и укажите данные подключения к вашей MongoDB и Timeweb S3 (см. раздел .env).
    `
        # Подключение к MongoDB
        MONGODB_URI=mongodb://admin:secret@127.0.0.1:27017/barrier_db?authSource=admin

        # Настройки сессии NextAuth
        NEXTAUTH_SECRET=generate_strong_secret_key_here
        NEXTAUTH_URL=http://localhost:3000

        # Timeweb Cloud S3
        S3_ENDPOINT=[https://s3.timeweb.cloud](https://s3.timeweb.cloud)
        S3_REGION=ru-1
        S3_BUCKET_NAME=your_bucket_name
        S3_ACCESS_KEY=your_access_key
        S3_SECRET_KEY=your_secret_key
    `

4. Запустить первичный сид базы:
    `
        npm run seed
    `
5. Запустить сервер разработки:
    `
        npm run dev
    `
Приложение будет доступно по адресу http://localhost:3000.


### 📌 Памятка разработчику / Где вносить правки
1. Изменение стоимости тарифа:
   - В обработчике чеков: app/api/admin/payments/route.js (переменная дневной/месячной ставки).
   - В расчёте дней долга нового жителя: app/api/admin/users/route.js (формула 700 / 2.5).

2. Изменение длительности Grace-периода (сейчас 7 дней):
   - В логике биллинга: app/api/admin/cron-billing/route.js (overdueDays >= 1 && overdueDays <= 7).

3. Контакты и реквизиты в личном кабинете:
   - Номер шлагбаума и чат поддержки: components/dashboard/InfoBlock.jsx.
   - QR-код для перевода: изображение в public/qrBank.jpg.
